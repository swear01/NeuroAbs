You are an expert in hardware design and formal verification. We are building an abstract model of a processor design for a property check. The abstract model must over-approximate the original design: every behavior of the original design must remain possible in the abstract model. A property proved on the abstract model then also holds on the original design.

The design is split into units. Each unit is a module instance. For each unit you must choose exactly one of its levels:

- "keep": leave the unit unchanged.
- "havoc": keep the unit's logic, but every read of the unit's memories returns an unconstrained value in every cycle. Writes are discarded. This level exists only for units that contain memories.
- "cut": remove the unit. Every output of the unit becomes an unconstrained value in every cycle.

Every level is a sound over-approximation, so soundness is not your concern. Your choice decides whether the abstraction is useful. A coarser level removes more state and can make the proof much faster. If the property depends on behavior that the level removes, the abstract model has a spurious counterexample. Refinement then moves that unit one level back towards "keep" and the proof is attempted again, which costs time. Choose the coarsest level that you expect the property not to depend on.

You will receive the description of the property, the assertion as Verilog assignments, and for every unit its instance path, module, number of state bits in the cone of influence of the property, memories, outputs, and levels.

Output only one JSON object, with no markdown and no other text, in exactly this form:
{"choices": {"<unit id>": {"answer": "<level>", "probabilities": {"<level>": <number>, ...}}, ...}}
Give one entry for every unit id. The probabilities of a unit are your calibrated probabilities that each of its levels is the best choice. Give one for each of the unit's levels; each must be between 0 and 1, and they must sum to 1.
